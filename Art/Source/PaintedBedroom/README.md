# Painted Bedroom: drop-in Unity package (experiment)

A walkable, fully 3D version of Van Gogh's *The Bedroom*, made by Serena Deng
with Claude. From the painter's spot it lines up with the canvas. From anywhere
else it is a real room: every object is a separate 3D model you can walk
around, pick up, turn over and put back.

**Where things are (one copy of the room since 10/25).**
- **`Assets/InnerFrameBedroomWeb/`**: the package Unity plays: the room data (`Data/`), the
  importer and builder (`Editor/`), the runtime scripts and the physics table, and what Unity
  builds from them (`Generated/`, `Scenes/`). This is the only copy of the room data.
- **This folder, `Art/Source/PaintedBedroom/`**: the sources the data is made from, outside
  `Assets/` so Unity doesn't import them: the Blender file and its export tool (`blender/`), the
  before/after tools (`tools/`) and the original generator (`web/`, archived since the freeze).

Like a Photoshop file and the PNG exported from it: you edit `blender/painted_bedroom.blend`,
export, and the export lands in the game's `Data/` directly.

## Try it (about 2 minutes)

Unity 6000.3.23f1, the InnerFrame project (URP, Input System, XRI 3.3.2).

`Assets/InnerFrameBedroomWeb/` comes with the repo, so there is nothing to copy.

1. Open `Assets/InnerFrameBedroomWeb/Scenes/PaintedBedroom.unity`. The built
   scene is committed, so you can press Play straight away.
2. To rebuild it from `Data/` (after a new export, see
   [Updating to a new export](#updating-to-a-new-export), or if the scene looks
   out of date): **Tools > InnerFrame > Painted Bedroom > Import and Build (no Blender)**.
   It rebuilds `Assets/InnerFrameBedroomWeb/Generated/` (meshes, materials, a
   prefab) and the scene.
3. Press Play and click in the Game view. The first click only captures the
   mouse.

Ignore the menu item **Build Scene from Blender FBX**: that route needs a
Blender FBX export that the project doesn't use.

**Re-running Import and Build rebuilds `PaintedBedroom.unity` from scratch.**
Any changes you made by hand in that scene are lost. To experiment in Unity,
save a copy first (File > Save As), and work in the copy. Physics, grab and
rig settings don't need this: they live in the
[physics table](#tuned-settings-the-physics-table), which a rebuild never
touches.

| Key | Action |
| --- | --- |
| W A S D, mouse | Walk, look (Esc releases the mouse) |
| Hold left click on an object | Carry it; scroll nearer/farther, Z/X turn it |
| Right-click (or I) on an object | Inspect it: turn it any way with the mouse, right-click to put it back |
| Backspace | Put everything back where the painting has it |
| F | Fly through furniture (Q/E down/up) |
| P | The painter's exact view, framed like the canvas |
| R | Back to the start |

On a Quest, the scene uses the team's XR Origin (XR Rig) from the XRI Starter
Assets, the same as the Gallery. It is set up so you grab with grip (near or
with the ray) and teleport anywhere on the floor. **This has not been tried on
a headset yet** (see below).

| Quest controller | Action |
| --- | --- |
| Right thumbstick forward, aim the arc, let go | Teleport (the floor is on the **Teleport** interaction layer) |
| Left thumbstick | Walk |
| Grip, near or with the 2 m ray | Grab what the physics table makes liftable |

**After Import and Build, run Tools > InnerFrame > Apply XR Rig Settings
(2 m ray, 0.8 scale, teleport floor).** The rebuild puts the teleport floor
back on the Default interaction layer, where the thumbstick arc can't land.
The tool (`Assets/Script/Editor/XRRigSettings.cs`) moves every Teleportation
Area and Anchor in the Gallery and this scene to the Teleport layer, and saves
the ray length and rig scale on each scene's XR Origin. Pointing at the floor
and pressing grip no longer teleports.

## What's inside

## Updating to a new export

The room data exists once, in `Assets/InnerFrameBedroomWeb/Data/`. To change the room:

1. Edit `blender/painted_bedroom.blend` and export (see `blender/README.md`). The export writes
   straight into `Assets/InnerFrameBedroomWeb/Data/`.
2. In Unity, run **Tools > InnerFrame > Painted Bedroom > Import and Build (no Blender)**.
3. If material names changed, delete the old materials left in
   `Assets/InnerFrameBedroomWeb/Generated/Materials/` in Unity's Project window. Import and Build
   creates new ones but never deletes.
4. Press Play. The physics table (below) is applied automatically; its rows match objects by name.
5. Commit the `.blend`, the changed files in `Data/` and what Unity rebuilt (`Generated/`,
   `Scenes/`, any new `.meta`) together, staged by name.

Importer and builder changes are made in `Assets/InnerFrameBedroomWeb/Editor/` directly. Before
10/25 there was a second copy of the whole package here, which drifted from the one in `Assets/`
(#107's room only reached the game in #108); it was removed.

## Tuned settings: the physics table

`Assets/InnerFrameBedroomWeb/Resources/PaintedBedroomPhysicsTable.asset` holds
every hand-tuned value. Import and Build never writes there, so the values
survive any number of re-imports. They're applied each time the scene starts,
in the editor and in a build. Nothing needs adding to the scene.

### What it holds

| Field | Default | What it sets |
| --- | --- | --- |
| **VR rig: Rig Scale** | 0.6 | XR Origin scale: you are smaller, so the room feels bigger |
| **VR rig: Ray Distance** | 1 m | How far the controller rays reach (the teleport ray keeps its own) |
| **Desktop rig: Desktop Scale** | 0.6 | Desktop player's eye height (1.6 → 0.96 m) and body size |
| **Desktop rig: Desktop Reach** | 1 m | How far away the dot picks things up (the builder's default is 6 m) |
| **Rows: Object Name** | | The object's name in the room, e.g. `Carafe`. Must match exactly |
| **Rows: Liftable** | on | Can be picked up, in VR and on desktop |
| **Rows: Has Physics** | off | Real physics: falls, gets pushed, can be thrown. Off = stays where it's put |
| **Rows: Rest Until Grabbed** | on | With Has Physics: stays exactly as painted until first picked up |
| **Rows: Use Gravity** | on | Falls when let go (needs Has Physics) |
| **Rows: Mass** | 1 kg | Heavier follows the hand more slowly and is thrown less far (needs Has Physics) |

Objects with no row keep the builder's setup: liftable, no physics.

### What the committed table says (2026-10-15)

- **Rig:** Rig Scale 0.8, Ray Distance 2 m, Desktop Scale 0.8, Desktop Reach
  2 m. The tool above saves the same 0.8 and 2 m on the XR Origin: change both
  together, or the Gallery and the bedroom won't match.
- **Liftable, with physics:** Pitcher, Carafe, Tumbler, Bottle_Tall,
  Bottle_Short, SoapDish, BrushBox, ClothesBrush, Pillow_Front, Pillow_Back,
  Hat (1 kg, rest until grabbed), Chair_Front (60 kg), Chair_Back (100 kg).
- **Fixed** (not liftable, no physics): Bed, Washstand, Basin, both doors, the
  window, the mirror, the pictures, the peg rail, the blanket, the towel and
  the hanging clothes.
- **Why the Washstand and Basin are fixed:** the Pitcher stands inside the
  Basin's box collider. Grabbing the Basin gave it physics while the resting
  Pitcher stayed frozen inside it, so Unity pushed the Basin down through the
  washstand's thin top. A movable washstand also left everything on it hanging
  in the air.
- **Keep Rest Until Grabbed on for the Pitcher.** Without it, physics starts
  with the Pitcher overlapping the Basin's box, and it gets pushed out of the
  bowl. Put back after a grab, it rests on top of the Basin's box, a few cm
  higher than painted.

### How to tune

1. Select the table in the Project window and press Play.
2. Edit it in the Inspector. Changes show at once, and because the table is
   an asset, Unity keeps them after Play mode.
3. If you tuned a Rigidbody, the XR Origin or the desktop grabber directly
   instead, click **Copy Current Values from Scene** before stopping Play.
   Unity discards edits made on scene objects in Play mode.
4. **Add Rows for Movable Objects in Open Scene** adds a row for every object
   that has none, filled with its current values.
5. Commit the table.

Outside Play mode, the Inspector shows the builder's values (scale 1, eye
height 1.6, reach 6). That is expected: the scene always keeps the builder's
values, and the table changes them at each start.

If the web room renames an object, its row stops matching. On Play, the
Console names the row.

### How it works

- **`Runtime/PaintedBedroomPhysicsTable.cs`:** the table asset's layout.
- **`Runtime/PaintedBedroomPhysicsApplier.cs`:** applies the table. When a
  scene loads, it checks for bedroom objects (`PaintedBedroomMovable`). If it
  finds any, it adds itself to the scene and loads the table from
  `Resources/`. It then sets each object's Rigidbody, grab and liftable flag
  by name, plus the XR rig and the desktop rig. It runs once, when the scene
  loads, and has no per-frame cost. In the editor it re-applies when the
  table is edited in Play mode.
- **`Editor/PaintedBedroomPhysicsTableEditor.cs`:** the two buttons under the
  table.
- **Rest Until Grabbed and push-out speed.** The builder fits one box
  collider around each part, and many of those boxes overlap: the pillows by
  25 cm, the blanket and the bed by 22 cm, what stands in the basin by 3 to
  9 cm. With physics from the start, Unity pushed them apart at up to 10 m/s
  and everything flew. So objects with physics stay frozen as painted until
  first picked up. Any remaining overlap pushes apart at 0.5 m/s at most.
- **The desktop rig is sized, not scaled.** Scaling its transform would put
  the painter's view (P) at the wrong height. So the walker's eye height and
  CharacterController shrink instead, and P still shows the painter's exact
  eye.

Changes to existing scripts (in `Assets/` only):
- **`PaintedBedroomMovable.cs`:**
  - adds `liftable` and `restUntilGrabbed`
  - `Wake()` turns physics on at the first grab
  - `ApplyWeightToGrab()` is public, so the grab feel follows the table's
    mass, and switches back to the builder's grab when physics is off
  - **Backspace** puts resting objects back to rest
- **`PaintedBedroomDesktopGrabber.cs`:** skips objects that aren't liftable,
  and wakes resting ones when grabbed.

Known limits:
- If the basin is picked up while the pitcher still rests in it, the two
  boxes overlap, so the basin is slowly pushed away. Better-fitting colliders
  in the builder would fix this.
- A networked grab script that records whether an object starts frozen, and
  keeps it that way, would leave resting objects frozen for good. Keep this in
  mind when multiplayer comes to the bedroom.

## How it was made

The room was built as a procedural three.js scene and fitted to the painting
from the painter's viewpoint. Colours were measured, and objects were placed
and scaled by comparing outlines against the canvas. It was then exported to
this format. The scene's source and the export tools are in `web/`; see
`web/README.md` to change the room and re-export.
- Every texture is drawn by code: brushstroke canvases, including the small
  pictures on the walls.
- No pixels from the painting or from any third-party asset are included.
- Outlines are inverted-hull "ink" shells, so they work in VR.

## Known gaps (next steps)

- **The painterly look in Unity:** colour grading and a URP ink effect. The
  web study's screen effects did not carry over.
- **Natural interactions:**
  - casements and doors on hinges
  - a sliding drawer
  - pictures that snap onto nails and clothes onto pegs

  Gravity is now set per object in the physics table (above). Objects
  without physics are still grabbed and floated freely.
- **Quest testing:**
  - frame rate with shadows on
  - about 450 meshes (combine the fixed ones if needed)
  - texture memory
  - comfort and room scale
  - hands vs controllers
