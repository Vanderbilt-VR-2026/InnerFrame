# Painted Bedroom: web source (three.js)

> **Web only, not part of the Quest app.** Nothing in this folder goes into the
> Unity project or the Quest build: Unity never reads these files. They are the
> browser version of the room (three.js), plus tools that export it to the Unity
> package. You only need them to reshape the room's objects or repaint its
> textures. To run the room in Unity or on a Quest, use
> `../InnerFrameBedroomWeb/` (see `../README.md`).

This is where the Painted Bedroom room is authored. `index.html` is a self-contained
three.js (r170) scene. Every object and every brushstroke texture is generated by
code and fitted to Van Gogh's painting from the painter's viewpoint. The Unity
package next door (`../InnerFrameBedroomWeb/Data/`) is exported from this page.

You only need this to **change the room itself** (reshape an object, move it, repaint
a texture) and re-export. To use the room in Unity, see `../README.md`.

## Open it in a browser

The page loads three.js from the jsdelivr CDN, so you need to be online. It also
shows the reference painting from `Assets/Art/Painting/`, so serve it from the
**repo root**:

```
cd <your InnerFrame folder>
python3 -m http.server 8000
```

Then open http://localhost:8000/Art/Source/PaintedBedroom/web/index.html.

- Drag to look around, WASD to walk.
- P returns to the painter's view.
- The buttons switch between painting view, walk mode, ink outlines, and a
  side-by-side comparison with the painting.

## Re-export to Unity

Needs Node.js 18+.

```
cd Art/Source/PaintedBedroom/web/tools
npm install playwright
npx playwright install chromium
node export_unity.mjs ../../InnerFrameBedroomWeb/Data
```

This writes `room.json`, `room.bytes` and `Textures/tex_###.png`. It runs headless
and takes a few minutes, because the textures are painted on load. Then:

1. In Unity, run **Tools > InnerFrame > Painted Bedroom > Import and Build (no Blender)**
   again.
2. Commit the changed data files, which are stored in Git LFS.

Things to know:

- **Without network access to the CDN**, set `THREE_LOCAL=/path/to/three.js` (a
  checkout of three.js r170 that includes `examples/jsm`).
- **Material names:** a few unnamed materials get a random suffix in `room.json`
  (e.g. `Paint_c3a49a_52`). Everything else is reproducible byte for byte.

## Check an export without Unity

```
node preview_unity_data.mjs ../../InnerFrameBedroomWeb/Data '[{"painter":true}]' ./preview
```

This rebuilds the data the way the Unity importer does, with similar lighting,
and saves `preview/view0.png`. Other views use `{"p":[x,y,z],"t":[x,y,z]}`: the
camera at p looking at t, with **x negated** from Unity coordinates.

## Where things are in `index.html`

The scene script is the `<script type="module">` block.

| What | Where |
|---|---|
| Room size and layout (walls, window, doors) | `ROOM`, `WIN`, `DOOR_L`, `DOOR_R`, `buildRoom()`, `buildWindow()`, `buildDoors()` |
| Furniture | `buildBed()` (`BED`), `buildTable()` (`TABLE`, the washstand and everything on it), the chair builders |
| Wall things | `hangPicture()`, `buildWallThings()` (pictures, mirror, towel, peg rail, clothes, hat) |
| The outside view | `buildOutside()` |
| Fit to the painting | `PAINT_VIEW` (the painter's camera: a shifted lens), `DISTORT` (per-object scale and offset), `GRADE` (measured colour grading per material) |
| Painted textures | `strokeCanvas()`, `paintMat()`, and the `M.*` materials |
| Export | `exportName()` (which object each mesh belongs to), `exportUnity()` (the format, cloth thickness, ink outline shells, glass opacity) |

**Coordinates:** the layout uses Unity-style left-handed numbers inside a group
mirrored on x. `exportUnity()` converts to Unity space: it negates x and reverses
the triangle winding.
