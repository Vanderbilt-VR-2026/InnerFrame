# Painted Bedroom: web source (three.js)

> **Web only, not part of the Quest app.** Nothing in this folder goes into the
> Unity project or the Quest build: Unity never reads these files. They are the
> browser version of the room (three.js), plus tools that export it to the Unity
> package. You only need them to reshape the room's objects or repaint its
> textures. To run the room in Unity or on a Quest, use
> `../InnerFrameBedroomWeb/` (see `../README.md`).

This is where the Painted Bedroom room is authored: a three.js (r170) scene in
`index.html` and `js/`, one file per object. Every object and every brushstroke
texture is generated by code and fitted to Van Gogh's painting from the painter's
viewpoint. The Unity package next door (`../InnerFrameBedroomWeb/Data/`) is exported
from this page. **Change the code here, never the exported files**: every export
rewrites all of `Data/`.

You only need this to **change the room itself** (reshape an object, move it, repaint
a texture) and re-export. To use the room in Unity, see `../README.md`.

## Open it in a browser

The page loads three.js from the jsdelivr CDN, so you need to be online. It also
shows the reference painting from `Assets/Art/Painting/`, so serve it from the
**repo root**:

```
cd <your InnerFrame folder>
python3 -m http.server 8000
```

Then open http://localhost:8000/Art/Source/PaintedBedroom/web/index.html.

- Drag to look around, WASD to walk.
- P returns to the painter's view.
- The buttons switch between the painting view, walk mode and ink outlines. A
  last button shows the painting in a corner for comparison.

## Re-export to Unity

Needs Node.js 18+.

```
cd Art/Source/PaintedBedroom/web/tools
npm ci
npx playwright install chromium
node export_unity.mjs ../../InnerFrameBedroomWeb/Data
```

`npm ci` installs the Playwright version pinned in `package.json`: the brushstrokes
are drawn by the browser, and a different Chromium draws them slightly differently,
so everyone must export with the same one. This writes `room.json`, `room.bytes`
and `Textures/tex_###.png` into the repo's copy of the package. It runs headless
and takes about 30 s (the textures are painted on load). Then:

1. **Copy the updated data into Unity.** Unity reads the copy inside your project's
   `Assets/`, not this folder. Replace `Assets/InnerFrameBedroomWeb/Data` with
   `Art/Source/PaintedBedroom/InnerFrameBedroomWeb/Data`, or copy the whole
   `InnerFrameBedroomWeb` folder in again.
2. In Unity, run **Tools > InnerFrame > Painted Bedroom > Import and Build (no Blender)**.
   This rebuilds the scene from scratch (see `../README.md`).
3. Commit the changed files in `Art/Source/PaintedBedroom/InnerFrameBedroomWeb/Data/`
   (the PNGs and `room.bytes` go to Git LFS automatically), on their own: `Data/` is
   exported once per round, by one person, from the merged source (see *Working
   together*). Don't commit `Assets/InnerFrameBedroomWeb`, `tools/node_modules` or
   `tools/preview`: `tools/.gitignore` leaves those out. `tools/package.json` and
   `package-lock.json` are committed: they pin Playwright.

Things to know:

- **Without network access to the CDN**, set `THREE_LOCAL=/path/to/three.js` (a
  checkout of three.js r170 that includes `examples/jsm`).
- **Stable names:** materials are named after their palette entry (`blanket`,
  `floor`...), or after their object when they have none (`Towel_paint`); texture
  files after their material (`tex_blanket.png`). A number is added only when two
  would share a name (`smock_2`). So adding or removing a material renames nothing
  else, and a diff of `Data/` shows only what changed.
- **Reproducible:** the same source exports byte for byte the same files (same
  Playwright version). To see what an export changed:
  `python3 ../../tools/compare_exports.py <old Data> <new Data>` (on the fixed-views
  branch, #44).

## Check an export without Unity

```
node preview_unity_data.mjs ../../InnerFrameBedroomWeb/Data '[{"painter":true}]' ./preview
```

This rebuilds the data the way the Unity importer does, with similar lighting,
and saves `preview/view0.png`. Other views use `{"p":[x,y,z],"t":[x,y,z]}`: the
camera at p looking at t, with **x negated** from Unity coordinates.

## Look at one object

```
node snapshot.mjs /tmp/chairs.png chairs
```

renders the painter's view of just that group, next to the painting
(`/tmp/chairs.png`, and `/tmp/chairs_render.png` alone). Groups: `room`, `window`,
`doors`, `bed`, `washstand`, `washstand_items`, `chairs`, `pictures`, `hangings`, or
a comma list; none for the whole room. In the browser, the same works with `index.html?only=chairs`.

## Where things are

`index.html` holds the page and loads the scene from `js/`, one file per object.
The files are plain scripts that share one scope, loaded in this order:

| File | What's in it | Unity objects |
|---|---|---|
| `js/core.js` | Shared by all: layout (`ROOM`), seeded randomness, brushstroke textures (`strokeCanvas()`, `paintMat()`), colour grading code, geometry helpers, the scene; the `M`, `GRADE` and `DISTORT` tables the object files fill; the two shared materials (`M.peg`: pegs and the door and drawer knobs; `M.string`: picture cords) | |
| `js/room.js` | Walls (with the openings for the window and doors: `WIN`, `DOOR_L`, `DOOR_R`), floor, ceiling, skirting | Room_Walls, Room_Floor, Room_Ceiling, Room_Skirting |
| `js/window.js` | Window frame, casements, panes, sill, and the 3D view through it | Window, Window_View |
| `js/doors.js` | Both doors, their frames and casings, the landing behind each | Door_Left, Door_Right, Door_Frames |
| `js/bed.js` | The bed: frame, mattress, pillows, blanket | Bed, Pillow_Back, Pillow_Front, Blanket |
| `js/chairs.js` | The chair builder (both chairs; their placement is in `app.js`) and the rush seat | Chair_Front, Chair_Back |
| `js/washstand.js` | The washstand itself: top, drawer, legs | Washstand |
| `js/washstand_items.js` | What stands on it (moves and scales with it) | Carafe, Basin, Pitcher, Tumbler, SoapDish, ClothesBrush, Bottle_*, BrushBox |
| `js/pictures.js` | The pictures and the mirror, and the painted canvases they show | Mirror, Picture_* |
| `js/hangings.js` | The peg rail and what hangs on it (smock, clothes, hat), and the towel on its hook | PegRail, Smock, Clothes_Dark, Cloth_Pale, Hat, Towel |
| `js/app.js` | Renderer, ink outlines, the painter's camera (`PAINT_VIEW`), controls, and the build order | |
| `js/export.js` | Export to the Unity format: object names, cloth thickness, ink outline shells, glass opacity | |

Each object file has the same three parts at the top: `<object>Materials()` (its
materials in the palette `M`), its `GRADE` entries (colour grading measured against
the painting) and its `DISTORT` entry (offset, scale and extra height to fit the
painting), then its builder.

Every object in the export belongs to exactly one file. To check, after adding
or renaming an object: `node coverage.mjs` (lists each group's objects; exit code 1
if one is missing or in two groups).

## What's attached to what

Moving one object can leave another floating. Check this before changing a position:

| Attached | How | So |
|---|---|---|
| Bedding on the bed | Children of the bed's group, one file | Move or `DISTORT` the bed: everything on it follows |
| Things on the washstand | Children of the washstand's group (`washstand_items.js` builds them on its top) | Move or `DISTORT` the washstand: they follow. Change their placement only relative to the top |
| Smock, clothes, hat on the peg rail | **Separate coordinates**, not children of the rail (`hangings.js`) | Moving the rail alone leaves them hanging in the air: move them together, by the same offset |
| Towel by the left door | Its own position, "just past the door casing" | After changing the left door (`doors.js`), check the casing doesn't cut through the towel |
| Pictures, mirror, peg rail, window, doors | Placed against the walls (`ROOM`, `WIN`, `DOOR_L`, `DOOR_R`, the slanted bed wall) | They follow when the walls change; changing `ROOM` moves all of them |

After changing a position, also snapshot the whole room (`node snapshot.mjs /tmp/all.png`),
not just your group, to see the contacts.

## Working together

- **One owner per object file.** Change only your objects' files. `core.js`,
  `app.js` and `export.js` are shared: say so before changing them.
- **Never rename an object** (the names in the table above): Unity scripts find
  objects by name.
- **A PR changes the source only** (`js/`), with a snapshot of the group before and
  after. `Data/` is exported once per round, by one person, from the merged source,
  and committed on its own. On a `Data/` conflict, export again; never hand-merge
  `room.bytes`.

**Coordinates:** the layout uses Unity-style left-handed numbers inside a group
mirrored on x. `exportUnity()` converts to Unity space: it negates x and reverses
the triangle winding.
